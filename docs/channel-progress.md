# Native run feedback

Telegram, Discord, Slack, Google Chat, Feishu and Lark show a small status message while a native channel request runs. Fast requests finish before a status message is created. Status changes are bounded to one update every three seconds, with a separate timeout and rate-limit backoff. A failed progress request does not stop the agent.

Telegram and Discord also use their native typing indicators. Slack, Google Chat, Feishu and Lark use the visible status message; Harness does not call an unavailable typing API. The current states are “Working…”, “Using a tool…”, “Checking the result…” and “Writing the response…”. Raw streamed text, reasoning, tool arguments and tool output are never included, so a credential split across chunks cannot leak through a partial preview. Live token-by-token response previews are not enabled.

The first final text chunk replaces the recorded status message. Additional chunks, attachments and interactive controls use the normal durable outbox. Receipt ownership includes the source request, user, channel and thread; the allowlist is checked again before edits and final delivery. A failed final edit retries the same recorded message instead of posting another final answer. Telegram's “message is not modified” response is accepted as a successful retry. Removing a status message can require operator intervention if its final edit cannot succeed.

Pauses stop the progress loop. Cancellation makes an owned status message show that the run was interrupted, without marking an outbox response as sent. On restart, an interrupted dispatch is not rerun automatically; any available status receipt is updated or left for its already queued final response. An uncertain status creation is recorded and never automatically repeated. If no receipt was returned, the eventual final reply is still delivered normally; the operator may need to remove an orphan status message.

Offline tests exercise an actual Agent through the gateway and silent CLI event observer, SQLite receipt recovery, cancellation during a pending create, approval pauses, allowlist changes, failed creates/edits, and native request contracts. No live channel account was used for verification.

Protocol references: [Telegram Bot API](https://core.telegram.org/bots/api), [Discord messages](https://docs.discord.com/developers/resources/message), [Discord typing](https://docs.discord.com/developers/resources/channel#trigger-typing-indicator), [Slack message updates](https://docs.slack.dev/reference/methods/chat.update/), [Google Chat message patches](https://developers.google.com/workspace/chat/api/reference/rest/v1/spaces.messages/patch), and [Feishu message updates](https://open.feishu.cn/document/server-docs/im-v1/message/update).
